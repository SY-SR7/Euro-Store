## النتيجة التنفيذية

تم تثبيت عقد واحد للهوية الفاتحة، المحتوى، المسارات، وواجهات البيانات بين واجهة الويب على الهاتف وتطبيق Expo/React Native. جميع عمليات بيانات المتجر في التطبيق الأصلي تمر عبر واجهات API نفسها الموجودة في مشروع الويب؛ لا توجد استعلامات مباشرة لجداول الأعمال من تطبيق الهاتف.

المقصود بـ 1:1 هنا هو تطابق عقد المنتج: نفس المحتوى، الترتيب، القياسات المستهدفة، الألوان، الأزرار، الحالات، المسارات، والنتيجة التي تكتب أو تقرأ من قاعدة البيانات. لا يمكن اعتبار ملفي PNG متطابقين ثنائياً لأن المتصفح وReact Native يستخدمان محركي رسم وخطوط مختلفين، ولأن لقطة التطبيق تحتوي شريط حالة/تنقل النظام. تتم مقارنة صندوق محتوى التطبيق بعد استبعاد system chrome وباستخدام الحالة والحساب واللغة نفسيهما.

## تغطية المسارات

تمت مطابقة 27 زوجاً من المسارات:

- المتجر: الرئيسية، المنتجات، تفاصيل المنتج، التصنيفات، تفاصيل التصنيف، العروض، وصل حديثاً، والمجموعات.
- الشراء: السلة، الدفع، نجاح الطلب، قائمة الطلبات، وتفاصيل الطلب.
- الحساب: الحساب، الملف الشخصي، العناوين، الولاء، الإشعارات، والمفضلة.
- ما بعد البيع: طلبات الاستبدال، إنشاء طلب استبدال، وتفاصيله.
- المشاركة والدعم: المفضلة المشتركة، FAQ، التواصل، الخصوصية، والشروط.

شريط التنقل السفلي يحافظ على الوجهات الخمس وترتيبها نفسه: الرئيسية، التصنيفات، السلة، المفضلة، الحساب، وارتفاع المحتوى 64px/dp.

## العمليات وقاعدة البيانات

- الرئيسية والتصنيفات والكتالوج وتفاصيل المنتجات والمخزون والخصومات تأتي من API الويب المشترك.
- السلة، الدمج بعد تسجيل الدخول، checkout، إنشاء الطلب، الإلغاء، إعادة الطلب، والتقييمات تستخدم endpoints الإنتاج نفسها.
- المفضلة، مشاركتها، وفتح رابط مشاركة عام تستخدم endpoints نفسها.
- الحساب والعناوين والولاء والإشعارات والاستبدالات تستخدم endpoints نفسها.
- التواصل والنشرة البريدية يكتبان فعلياً في `support_messages` و`newsletter_subscriptions` عبر المسارين `/api/storefront/contact` و`/api/storefront/newsletter`.
- لا يوجد أي استدعاء `.from(...)` داخل `apps/mobile` لبيانات الأعمال. استثناء المصادقة مقصود: جلسة Supabase Auth الأصلية، بينما تبقى كل بيانات الأعمال خلف API الخادم وسياساته.
- المشروع الفعلي المستخدم في ملفات البيئة هو `szhpqyvxodhaichrrdfb`. أزيلت وصلة Supabase المحلية القديمة إلى المشروع المحذوف لمنع تشغيل هجرات على هدف خاطئ.
- الهجرتان `20260830010000_support_messages.sql` و`20260830011000_newsletter_subscriptions.sql` مطبقتان على القاعدة البعيدة، وتم اختبار عمليتي POST حقيقيتين ثم حذف بيانات الاختبار بنجاح.

## فروقات اكتُشفت وأُغلقت أثناء الفحص

- إصلاح ترتيب شعار/بحث header وقياساته في RTL.
- إصلاح safe areas على Android باستخدام `react-native-safe-area-context` في جميع الشاشات الكاملة.
- إصلاح رابط بطاقة التصنيف: يفتح الآن `/categories/[slug]` مثل الويب بدلاً من تحويله إلى فلتر منتجات عام.
- إضافة بانري العروض و«وصل حديثاً» بالنصوص والبنية نفسها الموجودة على الويب.
- فصل النصوص القانونية إلى مدخل mobile-safe مشترك؛ منع سحب `jsonwebtoken`/`crypto` الخاصة بالخادم إلى حزمة React Native.
- ترقية تطبيق الهاتف إلى Expo 54 وReact Native 0.81.5، واستخدام Worklets plugin المدعوم.
- استبدال `expo-av` المهجور بـ `expo-video`.
- منع محاولة remote push داخل Expo Go فقط؛ تبقى الإشعارات مفعلة في development/preview/production builds الأصلية.

## حدود الإثبات

- لا يمكن تنفيذ runtime أو screenshot حقيقي لـ iOS من Windows. الشفرة والعقد وإعدادات Expo/EAS مشتركة، لكن ختم التحقق البصري على iPhone يتطلب تشغيل TestFlight/IPA على iPhone أو Simulator على macOS.
- المطابقة البكسلية الحسابية لا تشمل شريط حالة Android/iOS، شريط gesture، اختلاف rasterization للخط العربي، أو اختلاف حالة تسجيل الدخول. يجب توحيد الجهاز، اللغة، الحساب، حجم الخط، ومحتوى قاعدة البيانات قبل أي image diff.
- لا يدّعي هذا التقرير أن PNG المتصفح وPNG التطبيق متطابقان byte-for-byte؛ يدّعي ويثبت تطابق واجهة المنتج وبياناتها وتدفقاتها ضمن القيود الأصلية للمنصتين.
