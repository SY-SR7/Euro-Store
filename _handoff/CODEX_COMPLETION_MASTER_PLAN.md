# خطة إكمال Euro Store الشاملة

آخر تحديث: 2026-08-29

## النطاق والقاعدة

يغطي هذا التدقيق `EuroStore_PRD.md` وما يرتبط به في الويب والآدمن والهيلبر والشريك والموبايل وقاعدة البيانات المشتركة. لا تُشغّل أوامر build وفق `CODEX_LOCAL_RULES.md`؛ استُخدمت اختبارات وفحوص TypeScript وESLint وExpo Doctor بدلاً منه.

## حالة الخطة

1. **مطابقة PRD والجرد - مكتمل:** جرد المسارات والجداول والصلاحيات والتدفقات، وفصل المتطلبات الفعلية عن المسارات المكررة أو التجريبية.
2. **الويب والحساب والسلة والدفع - مكتمل برمجياً:** تسعير الخادم، سلة ذرية، idempotency، خصومات وولاء وإحالات، طلبات واستبدال وفواتير، ملفات خاصة، وصفحات قانونية، وفشل Sham Cash المغلق.
3. **الآدمن والصلاحيات وربط الأدوار المستقبلية - مكتمل برمجياً:** صلاحيات Sub-Admin مغلقة افتراضياً، TOTP، CRUD الكتالوج، التقارير، السجلات، الإعدادات الخاصة، وإدارة الهيلبر والشريك وطلبات المنتجات.
4. **الهيلبر والشريك والولاء والاستبدال - مكتمل برمجياً:** مسارات منفصلة حسب الدور، عمليات قاعدة بيانات ذرية، QR موقّع، مخزون حقيقي، تدفق الاستبدال بمساريه، وصور خاصة موقعة مؤقتاً.
5. **الأمان والخصوصية - مكتمل على مستوى الكود:** RLS، CSRF/origin، rate limits، رؤوس CSP، منع SSRF، قيود رفع الملفات، أسرار غير عامة، outbox محدود المحاولات، وإزالة تسريب الرموز وبيانات العميل للشريك.
6. **التوثيق والتسليم - مكتمل:** هذا الملف، تقرير الأمان، سجل المطابقة، وسجل المتبقي الخارجي.
7. **التحقق - مكتمل برمجياً:** نجح TypeScript لكل التطبيقات والحزم، وESLint بصفر أخطاء، و48 اختباراً، وExpo Doctor 17/17، وتدقيق الأسرار والأنماط الخطرة. لم يُشغّل build.
8. **الموبايل - مكتمل برمجياً:** ضيف/تسجيل، AR/EN وRTL/LTR، الهوية الفاتحة الموحدة، كتالوج وبحث وفلاتر خادم، variants وattributes ومعرض صور وفيديو ودليل مقاسات وحزم ومراجعات وشارات، سلة خادم وcheckout ذري، عناوين وولاء وQR وإحالة، طلبات وإلغاء وفاتورة وإعادة طلب، استبدال وصور وQR، مفضلة وإشعارات وpush واشتراك توفر. بقي اختبار وظائف الجهاز الفعلية على هاتف فقط.

## ما حُذف لأنه زائد أو مخالف

- مسارات API مكررة أو تتجاوز حدود الدور، ومنها مسارات سلة غير ذرية، مسارات ولاء عامة للهيلبر، ومسارات QR/استبدال قديمة.
- مسارات push-token الديناميكية التي كانت تضع الرمز الحساس في URL.
- نقاط اختبار وقواعد بيانات ومسارات إدارة قديمة لا تنتمي لسطح الإنتاج.
- إكمال الاستبدال دفعة واحدة حين يخالف تدفق PRD متعدد المراحل.
- إظهار معلومات شخصية للشريك لا يحتاجها لإتمام مهمته.

## شروط الجاهزية التشغيلية

- مشروع Supabase الحي `szhpqyvxodhaichrrdfb` متصل فعلياً، وسجل الهجرات المحلي والبعيد متطابق عند 75 هجرة.
- ضبط `LOYALTY_QR_SECRET` و`QR_SECRET` و`EXCHANGE_QR_SECRET` بأسرار مستقلة قوية، إضافة إلى أسرار Supabase والـ cron والبريد وExpo.
- الاعتماديات مثبتة ومتطابقة مع lockfile، وفحوص النوع والاختبارات ناجحة. يبقى build ممنوعاً حسب قاعدة المشروع.
- نجح اختبار عميل حي معزول 14/14: المصادقة، العنوان، السلة، رفض Sham Cash غير المهيأ، طلب COD، idempotency، خصم المخزون مرة واحدة، الفاتورة PDF، الإلغاء، وإعادة المخزون. حُذفت بيانات الاختبار بعده.
- ربط خدمة دفع Sham Cash الحقيقية قبل إتاحتها؛ التنفيذ الحالي يرفض استخدامها بأمان بدلاً من تسجيل دفع وهمي.
- تسجيل Expo push tokens من تطبيق الموبايل الفعلي، وضبط Resend وExpo وخدمة التوصيل في بيئة النشر.

## المتبقي داخل المستودع

- لا توجد فجوة وظيفية معروفة من متطلبات PRD ضمن Web أو Admin أو Helper أو Partner أو Mobile بعد جولة 2026-08-29.

## المتبقي خارج المستودع

- اختبار الكاميرا وQR وPush والتنزيل/المشاركة على جهاز Expo حقيقي.
- نطاقات الإنتاج وربط الاستضافة وحسابات متاجر التطبيقات لا يمكن إنشاؤها من المستودع.
- تزويد Resend/SMTP وExpo Push ببيانات حسابات حقيقية، وتوثيق مزود Sham Cash ومفاتيحه إن تقرر إطلاق الدفع الإلكتروني. COD يعمل الآن.
- مراجعة النصوص القانونية من مستشار محلي قبل الإطلاق التجاري.
