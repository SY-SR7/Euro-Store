# قواعد تشغيل Codex المحلية

- لا تشغل `next build` أو `turbo build` أو `pnpm ... build` في هذا المشروع، لأن أوامر البناء تتسبب بتوقف الاستجابة في البيئة الحالية.
- للتحقق استخدم فحوصاً غير بنائية مثل `tsc --noEmit --incremental false`، وعمليات `rg`/قراءة الملفات/مراجعة المسارات.
- إذا احتاج أي عمل مستقبلي إلى build فعلي، يجب طلب موافقة صريحة من المستخدم أولاً مع توضيح سبب الحاجة.

## تنفيذ عمليات Supabase

- استخدم الاتصال المباشر بالمشروع الحقيقي افتراضياً عبر Supabase JS/PostgREST أو اتصال PostgreSQL البعيد أو أوامر Supabase CLI التي تقبل `--db-url`.
- لا تشغّل Docker Desktop لقراءة بيانات Supabase أو تعديلها أو تطبيق migrations أو تنفيذ فحوصات الأمان عندما يتوفر مسار مباشر ينجز العملية.
- استخدم عميلاً خفيفاً ومباشراً لـ PostgreSQL عند الحاجة إلى SQL مخصص، مع إبقاء كلمات المرور والمفاتيح خارج المخرجات والسجلات.
- لا يُستخدم Docker إلا استثنائياً عندما يطلب المستخدم صراحة اختبار قاعدة محلية معزولة أو استعادة نسخة، أو عندما لا يوجد بديل مباشر مكافئ؛ ويجب توضيح السبب أولاً ثم إيقافه فور انتهاء العملية.

## سياسة الوسائط العامة

- يُمنع نشر أي صورة عامة تحتوي إنساناً من أي عمر، بما في ذلك الوجه أو اليد أو جزء من الجسم أو الظل أو الانعكاس أو العارضة أو المانيكان أو التمثال البشري.
- يجب أن تكون وسائط الكتالوج أصلية أو مملوكة/مرخصة بوضوح، وألا تعتمد على روابط صور خارجية مؤقتة.
- تُراجع كل دفعة وسائط بصرياً قبل النشر، ثم يُشغّل `scripts/audit-people-free-catalog.mjs` للتحقق من كل المراجع الحية.
- بعد استبدال أي دفعة، يُشغّل `scripts/purge-unreferenced-public-media.mjs` لحذف الملفات العامة غير المرتبطة ومنع بقاء أي أثر قديم في Supabase Storage.
